# Gentle Facts — real-repository baseline (October 2026)

Baseline for the `gaps.yaml` roadmap ("gentle-facts-gaps-and-improvement-roadmap").
Recorded BEFORE any optimization commit; all Sprint 1/2 improvements must report
deltas against these numbers. Generated by `scripts/benchmark-facts-real.mjs`
(`pnpm benchmark:facts:real`).

## Method

- Corpus: the 910 tracked files of this repository at commit
  `8c4c4d484209` (git archive copy in a disposable tmpdir; the live `.pi`
  cache, generation pointer and untracked user files are never read or mutated).
- 7 repetitions per scenario; `--expose-gc`; per-phase timings from the S0.1
  `FactsPhaseMetrics` instrumentation (durations aggregate per sync attempt).
- Machine: Linux (tmpfs corpus), Node 26.10.0. Timings are observations on
  this machine, not a production SLA.
- Scenarios: `cold` (empty cache), `warm` (unchanged tree),
  `postEdit` (one modified source file), `burst` (3 concurrent unchanged
  `sync()` calls; per-call times reported separately).

## Reading (maps to gaps.yaml observations)

- **OBS-001/002 (every query pays freshness work):** an unchanged query still
  costs p50 182.51ms, paid by every `facts_query`/`facts_dependents`/
  `facts_status` and by lifecycle hooks. Warm cost decomposes into
  module_resolution (~62ms/sync, 34%), snapshot_validation (~46ms), git_scan
  (~33ms) and cache_load (~30ms). Sprint 1 (workspace epoch + single-flight)
  targets these; Sprint 2 caches attack module_resolution and cache_load.
- **OBS-003 (no single-flight):** 3 concurrent unchanged syncs take 537.94ms
  wall — 2.95× the warm p50, i.e. fully serialized with zero coalescing. The
  21 queued callers accumulated 3749.26ms of pure queue wait, and each waiter
  repeated the full git_scan + module_resolution + snapshot_validation
  sequence (phase counts 21 = 3 callers × 7 repetitions, ×2 scans per sync).
- **OBS-004/005:** manifest extraction is negligible in the warm path, but
  module resolution dominates warm syncs and is recomputed in full every
  time (GF-P0-003 is the largest warm-path cache target).
- **OBS-006:** cache_save is only paid on publication (0 in warm/burst), so
  the history write fast path (GF-P0-005) concerns `recordFactsHistory`,
  which runs outside `sync()` and is instrumented but not part of these
  scenarios.

## Sprint 1 gate (2026-10-05, after the fast path landed)

Same harness, now with an `autoRead` scenario: a fast-path service primed by
one full sync, then unchanged auto-mode reads (deterministic scan-verified
freshness; only the cheap scan runs, resolution/validation/publication
skipped). Same machine, 7 samples, 915-file corpus at `755cafaa`:

| Scenario | min | p50 | p95 | p99 | max |
|---|---|---|---|---|---|
| warm full sync (same run) | — | 249.22 | 291.04 | 291.04 | 291.04 |
| **autoRead (fast path)** | — | **50.66** | **53.62** | 53.62 | 53.62 |

Unchanged reads are **4.9x faster** within the same run (p50), with the phase
breakdown showing only the verifying `git_scan` (~50ms) and zero module
resolution, snapshot validation, cache load or publication work. Correctness
is guaranteed by construction: the fast serve re-runs the authoritative
workspace scan and falls back to the full sync on any observed change, Git
boundary break or scan failure (fs.watch races cannot serve stale data).
Reproduce with `pnpm benchmark:facts:real`.

## Sprint 2 gate (2026-10-05, history memo + incremental resolution cache)

Same harness, 7 samples, 918-file corpus at `4e47e2ca`. The incremental
resolver cache serves unchanged importers from a per-root worker cache after
replaying their exact probe read-sets; full syncs therefore skip most of
TypeScript resolution while keeping the deterministic scan/validation path:

| Metric | Baseline (2026-10-05) | Sprint 1 run | Sprint 2 run |
|---|---|---|---|
| module_resolution per full sync | 62.5ms | 62.5ms | **26.7ms (-57%)** |
| warm full sync p50 | 182.51ms | 249.22ms | **152.45ms** |
| autoRead (fast path) p50 | — | 50.66ms | **39.47ms** |
| manifest per full sync | 0.5ms | — | 0.37ms (S2.1 deferred: <0.3% of sync) |

Cross-run wall-clock numbers carry machine variance; the phase-level
module_resolution delta is the within-harness measurement. The resolver-cache
equivalence test (incremental edges identical to a fresh resolution) is part
of the suite, and unchanged reads remain scan-verified for determinism.
Reproduce with `pnpm benchmark:facts:real`.

## Reproduce

```
pnpm benchmark:facts:real                     # 7 samples, 3 burst callers
FACTS_BENCH_SAMPLES=14 pnpm benchmark:facts:real   # tighter percentiles
```

The script prints JSON on stdout and progress on stderr. It asserts
self-checks per scenario (cold indexes >0 files, warm/unchanged and burst
calls index 0, postEdit indexes exactly 1) and fails loudly if any
self-check breaks.
