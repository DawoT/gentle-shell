# Codex Web and Facts reliability sprints

## Scope and acceptance

This backlog preserves the eight improvement areas approved after the completion audit. A successful individual fix does not close the whole roadmap.

1. Recovery: interrupted requests, tool calls/results and final responses must not silently replay. Persist execution identity and expose explicit recovery after process restart. Test each failure boundary independently.
2. Process containment: cancellation must settle all supervised descendants, with documented platform-specific limits. Detached descendants and Windows require additional containment.
3. Global admission: bound work across process registrations and sessions; demonstrate fair scheduling under competing sessions.
4. Producer budgets: prevent oversized results before complete serialization; provide pagination where the tool contract permits it.
5. Facts precision: resolve Python/Go modules with uncertainty labels, then add independently verified symbol relations. Import consumers are not function callers.
6. Workspace consistency: detect changing scans, retry within a budget and explicitly reject unstable snapshots. Existing source-hash/stabilization tests cover some races; this does not prove an atomic whole-workspace snapshot.
7. Types and compatibility: reduce the recorded diagnostic baseline and verify the supported Pi/runtime matrix. Pi 0.87.1 is the currently exercised SDK.
8. Observed ROI: opt-in usage/fallback/latency measurement; distinguish provider-reported tokens from byte-based estimates. Never infer billing or adoption from the demo.

## ADR: clean EOF delivery protection — 2026-09-27

**Classification:** R2/M, shared concurrency and capability lifetime. Implementation and independent semantic review share a writable filesystem. This is not mechanically isolated approval or merge certification; no commit, merge or publication is authorized by this record.

**Problem:** the transport previously treated a clean HTTP EOF as complete delivery. Pi's SDK correctly rejected a missing terminal event, but an explicit retry with the same user context could submit a second model request on that same turn. There is no evidence that Pi executed partial tool calls.

**Decision:** a separate bounded SSE observer validates framing and response identity while preserving response bytes. Successful SSE must contain a dispatched terminal event. A completion for another response, malformed frame, incomplete UTF-8, event exceeding 8 MiB, missing terminal or accepted response with no body marks the turn uncertain and requests scoped cancellation. An uncertain turn stays blocked; inspection does not unlock it. A distinct user turn can proceed using the existing session capability.

**State transitions:** ordinary request -> streamed delivery -> known terminal/EOF permits continuation. Ambiguous transport or malformed delivery -> uncertain turn -> scoped cancellation -> no same-turn resubmission. Explicit failed/incomplete/error events are recognized as terminal protocol outcomes; if the SDK cancels their still-open transport, that cancellation retires the turn. Agent abort retains its existing semantics during local tool execution.

**Limits:** this is in-memory protection for a living Pi client. It is not durable execution journaling, automatic recovery, an exactly-once side-effect guarantee or a host command settlement assertion. Node/OpenAI SDK may show a generic connection error even when transport evidence is more precise. HTTP rejections preserve their original status. The observer bounds one accumulated SSE event, not all response producer allocations.

**RED:** `/tmp/recovery-eof-corrected-red.log` demonstrated missing rejection for clean EOF and foreign completion. `/tmp/recovery-bodyless-red.log` demonstrated the accepted bodyless branch and bare-data framing omission. An intermediate green run failed because the test expected the word “completion” instead of “terminal”; that assertion mismatch is not reported as a production defect.

**GREEN:** 15 recovery cases passed in `/tmp/recovery-final-focused.log`, including real SDK same-user retry suppression, a distinct new user, explicit failure on an open connection, CRLF/multiline/single-byte UTF-8 framing, event budgets and known HTTP rejection. Earlier focused bridge/client/provider/inspection/runtime coverage passed 38 cases. The joint actual HTTP/Pi runtime probe passed twenty rounds, eight inspections, scoped cancellation and zero retained capabilities (`/tmp/recovery-composed.log`). Production-installed Facts and bridge SDK probes passed (`/tmp/recovery-packed.log`). A live ChatGPT SDK response returned PI_WEB_OK (`/tmp/recovery-live.log`), using an owned temporary committed workspace removed afterward.

**Deployment:** daemon, launcher, tunnel and existing visible Pi remain running. A new SDK session exercised the updated source. An already-loaded visible Pi session does not acquire edited extension modules automatically; open a fresh Pi session to load the fix. No daemon restart was required because this change is in the Pi client.

**Next recovery work:** durable session/turn identity and execution receipts, followed by daemon/browser restart fault injection. The remaining seven roadmap areas above are not declared complete by this ADR.

## ADR: durable Pi tool admission — 2026-09-27

**Classification:** R2/M, shared concurrency and local side effects. The existing Pi tool hook writes an exclusive, private claim before permitting execution. The claim and parent directory entries are fsynced on POSIX. Reopening the same persistent Pi session cannot execute the same `toolCallId` again. A settlement receipt captures a result observed by Pi's hook; it is not a claim that the external effect or final transcript was committed. A failed settlement leaves the claim blocked and reports uncertainty. In-memory SDK sessions retain a bounded per-session map while the extension process lives. Other model providers do not use this bridge journal.

**Failure states:** `absent -> admitted -> result-observed`. There is no automatic transition back to absent. Concurrent claimers use exclusive publication; one wins. A partial/corrupt claim, foreign settlement, unavailable storage, symlinked session directory or interrupted admission lock blocks execution. The read-only `/web-bridge recovery` command bounds its directory scan and uses hashed call references. Raw commands/results are not persisted in receipts. No full-session replay is attempted.

**Tests:** RED for reopened admitted/settled replay (`/tmp/tool-recovery-red.log`), memory-session switching (`/tmp/tool-recovery-memory-red.log`), display injection (`/tmp/tool-recovery-display-red.log`) and symlinked session parent (`/tmp/tool-recovery-parent-red.log`). GREEN includes two OS processes racing, SIGKILL before/after an owned fixture effect, corrupt claim/foreign settlement, storage failures, memory switching, result-hook failure warning, non-bridge isolation and actual installed Pi runtime admission (`/tmp/tool-recovery-parent-green.log`, `/tmp/tool-recovery-final2-focused.log`, `/tmp/tool-recovery-final2-packed.log`). Process-crash tests do not simulate loss of power or verify filesystem hardware flush behavior.

**Residual scope:** daemon/browser restart, durable model turn identity, host-side tool execution receipts, crash during response delivery, and semantic command deduplication remain open. A session copied/renamed or a new call ID is a different scope. The session transcript may not be reopenable if Pi dies before it first persists an assistant entry. Windows does not provide the same tested directory fsync semantics. A stale admission lock requires verified operator intervention; it is never automatically removed. Local storage can be changed by the owning user, so this is not a security boundary against same-user tampering. This is an incremental guard, not completion of backlog item 1.

**Review and release:** an independent read-only architecture review found the memory-switching and parent-sync gaps; both were remediated. That reviewer later exhausted its tool quota before a final code review. The worktree is shared and no cryptographic A/V approval or mechanical isolation has been established. This change is not certified for merge or publication. The existing launcher/daemon/tunnel/visible Pi remain running; an already-loaded Pi session needs a new session to load these extension changes.

## ADR: persistent model turn identity — 2026-09-27

The bridge provider now derives a stable host turn ID from the Pi session scope and latest user-message digest, and writes an exclusive model admission receipt before its first model POST. A new provider/process using the same persistent session path cannot submit the same user turn again. Within one live provider, subsequent tool/model rounds of that admitted turn remain possible; concurrent streams of the same turn are rejected while a request is active. A distinct user message gets a new turn. The stored claim carries no prompt text. This is a conservative anti-replay guard, not a resumable transaction.

The model receipt remains in admitted state after completion; it does not assert final transcript persistence. Existing session-copy, new-call-ID, local-storage tampering and Windows durability limits still apply. This is not semantic exactly-once execution. The independent reviewer and cryptographic merge gate must evaluate the final diff before publication.

## ADR: host model metadata across daemon restarts — 2026-09-27

**Classification:** R2/L. The former host turn inspection lived only in daemon memory, so a fresh capability could not inspect whether an interrupted model turn had been admitted or completed. Persistent Pi sessions now pair with a digest-only recovery scope. The host stores a private, ordered admission before model execution and writes separate completion/cancellation milestones. Re-pairing with the same scope permits authenticated, read-only inspection. Reusing the same turn ID in that scope is rejected, including after a daemon restart. In-memory Pi sessions retain the existing live-only behavior.

The host reports `unobserved`, `admitted`, `model-completed` or `cancelled`, a last completed sequence/response ID, and `replay_allowed: false`. This is host model evidence: it cannot establish that the stream reached Pi, the Pi transcript was saved, or external tool effects settled. No prompt, tool arguments/results, model body or capability are journaled. Directory ownership/mode, bounded records, exclusive admission and POSIX sync guard ordinary restart failures; local same-user tampering and Windows directory durability remain outside the guarantee. The bounded journal has no automatic retention cleanup yet.

The first implementation used a separate order reservation and claim. Independent read-only review found that a crash between those writes could strand the whole scope. A RED race test required a single admission record; the design now publishes one ordered claim. Review also found that creating its final name before writing it exposed partial data to concurrent readers. The claim is now fully written and synced under a temporary name, hard-linked to the exclusive ordered name, then directory-synced before model execution. A pre-publication crash leaves an ignorable temporary file. The reviewer also found orphan outcomes permitting turn replay, completed turns mislabelled on graceful removal, and timestamp ties hiding later admissions. Those cases have dedicated regressions and pass after correction. OS `SIGKILL` cases cover a held stream and a completed nonstream response, followed by re-pairing.

Final gates: bridge 1,447 passed, 12 skipped, zero failed across 130 files (`/tmp/host-recovery-bridge-final.log`), plus typecheck and bundle integrity. Gentle Shell 4,128 passed, 41 skipped, zero failed, followed by provider-contract/runtime-harness (`/tmp/host-recovery-gentle-full.log`); 60 focused bridge tests passed, typecheck retained 188 known diagnostics without regression, generated modules matched, packed Facts/SDK and package resources passed. ## ADR: contain local shell descendants on delegated Linux — 2026-09-27

**Classification:** R2/M. A foreground or background Chat-First shell started in its own POSIX process group, but a descendant using `setsid` escaped group cancellation and wrote after the parent had been killed. RED reproductions are `/tmp/process-containment-red.log` and `/tmp/process-containment-background-red.log`.

On Linux when the current cgroup v2 hierarchy permits child cgroups, each local command now joins a private cgroup before executing. Cancellation and timeouts signal both the cgroup and the original POSIX process group; the latter also closes the race before cgroup join. Normal command completion retires remaining cgroup descendants. Without delegation, the existing POSIX process-group fallback remains. Windows still terminates only the root child. A same-UID command that deliberately migrates out of a writable cgroup remains outside this guard, so this is operational cleanup and not an adversarial sandbox. The cgroup is removed after close, with bounded retries if the kernel has not yet released it.

Foreground/background detached-descendant tests and immediate cancellation stress cases passed. The final bridge suite passed 1,452 tests, skipped 12 and failed zero across 130 files (`/tmp/process-containment-full.log`); typecheck and bundle integrity passed. Independent read-only review found the pre-join cancellation race; signalling both cgroup and process group fixed it, and the final review found no concrete blocker. The launcher supervised a clean source-daemon restart while its tunnel and visible Pi stayed active. This remains shared-worktree review without cryptographic A/V approval. Remaining process-containment work: Windows Job Objects or equivalent verified tree ownership, and a stronger OS isolation boundary if intentionally evasive commands must be contained.

## ADR: cross-process Chat-First admission — 2026-09-27

**Classification:** R2/L, shared command concurrency and crash recovery. `/tmp/global-admission-red.log` showed two independent Chat-First MCP processes using one configured home each admitting a background command despite `maxConcurrent=1`. The old in-memory semaphore had one instance per registration.

A private SQLite ledger now serializes admission across those processes. Foreground calls wait in a bounded FIFO queue; background calls reject immediately when capacity or an older queue is occupied. Task ownership and logs remain local to each MCP registration. Normal MCP stdin close cancels foreground calls and terminates owned background tasks; a slot releases only after command close. An abruptly killed owner leaves its lease occupied because its descendants may continue. Exact-ID CLI recovery requires operator confirmation of descendant settlement. On Linux, boot ID, PID namespace and process start ticks distinguish a recycled PID. An unknown owner identity also requires separate confirmation that the original owner is offline. A proven live owner cannot be recovered. This is an operational capacity guard, not a command sandbox, effect rollback or automatic crash recovery.

Focused RED/GREEN evidence covers two real MCP processes, FIFO, cancellation, timeout, configuration changes, transport EOF, SIGKILL and recovery through the CLI (`/tmp/global-admission-{red,recovery-red,focused9}.log`). The independent read-only reviewer identified permanent capacity loss, PID reuse and reboot/legacy recovery gaps; each led to a correction and its final pass found no further concrete R2 blocker. The writable worktree is shared and lacks mechanical A/V isolation or signed merge approval. Full suite and packaging results are recorded after final gates below.

### Next context and observability increment

Use Pi's existing session compaction lifecycle as the checkpoint owner. Keep the complete transcript on disk; construct each model request from the current objective and constraints, a branch-specific checkpoint, unresolved tool calls, recent conversation and selectively retrieved evidence. The checkpoint records source entry IDs, workspace revision, evidence hashes, uncertainty and pending work. Historical Facts receipts are evidence about a past workspace and must be refreshed before supporting claims about current files.

Admission should measure serialized bytes and estimated tokens by component before sending. Set a configurable target budget below the model's accepted ceiling, reserve output/tool headroom, and compact before multipart staging. Never silently truncate the latest user request, governing instructions or unmatched tool calls. If indispensable context alone exceeds the budget, surface a specific budget failure. Compaction must finish before model admission; retain the existing execution journal and replay fences. Do not use `previous_response_id` as an unverified shortcut around recovery identity.

Implement this in stages: (1) request-size telemetry and a budget decision visible to Pi; (2) branch-aware checkpoint integration with the installed compaction API; (3) retrieval from transcript/Facts with digest validation; (4) replay benchmarks that compare goal/constraint preservation and actual payload sizes. A smaller payload is insufficient if the agent loses an unresolved obligation. Report estimated tokens separately from provider usage; do not claim a savings percentage before measurement.

Unify MCP lifecycle events through a bounded, rotated structured sink. Link trace ID, turn ID, broker call ID and native session ID, with elapsed time and terminal reason, without command contents or credentials by default. Expose the actual log destination in diagnostics; an unused legacy `mcp.log` should not imply that MCP has no observability. Separate transport timeout from command exit and cancellation request from confirmed process settlement.

Producer budgets remain open: read_file currently reads the complete file before slicing; grep buffers matches before truncation; command output limits need byte-based streaming accounting. These require bounded producers and honest truncation/pagination metadata, not only a final response-size check.
